# Kestrel16

A 16-bit computer designed from the gates up, with its own toolchain.

- **The machine:** a 16-bit RISC-style CPU with 8 registers, 64 KB of memory, memory-mapped I/O in 8 slots on a 32-pin backplane (a UART card, a timer and an interrupt controller so far) and interrupts.
- **A reference emulator:** the definition of correct behaviour.
- **A C compiler:** structs, pointers, arrays, a preprocessor, and most of C (no floating point).
- **An assembler:** labels, expressions, directives and pseudo-instructions.
- **A gate-level simulator and circuit editor:** the real CPU, built from gates, ROMs and RAM chips modeled on 74HC parts. It runs the same programs as the emulator and gives the same answers.

See [ARCHITECTURE.md](ARCHITECTURE.md) for how the code is organized.

## Build

You need CMake, a C++17 compiler and Python 3. On Windows, use MSYS2 MinGW-w64.

```sh
cmake -S . -B Build
cmake --build Build
ctest --test-dir Build
```

Executables go to `Binary/`, and the example programs to `Binary/Programs/`.

## Usage

Run a C or assembly program on the emulator (it is built first):

```sh
Binary/KestrelEmulator --run Programs/Fibonacci.c
Binary/KestrelEmulator --run Programs/Shell.c        # interactive; type 'help'
Binary/KestrelEmulator -t Binary/Programs/Interrupts.bin  # trace each instruction
```

Run the same program on the gate-level computer:

```sh
Binary/KestrelSimulator --run "Kestrel16 Computer" --program Programs/Fibonacci.c
```

Open the circuit editor:

```sh
Binary/KestrelSimulator
```

Use the tools on their own:

```sh
Binary/KestrelCompiler prog.c          # → prog.s
Binary/KestrelAssembler -l prog.s      # → prog.bin, with a listing
Binary/KestrelEmulator prog.bin
```

The CPU's components are generated from `Tools/` (Python 3) as part of the build, and again
whenever a generator or a definition header changes. To regenerate them on their own:

```sh
cmake --build Build --target hardware
```

The same components open in KiCad 9 as schematics: one sheet per component, with each primitive
swapped for a 74HC chip (or ROM, RAM, ...) from `Tools/eda/parts.yaml`. The project lands in
`Build/KiCad/Kestrel16 Computer/`. This needs PyYAML (`pip install pyyaml`).

```sh
cmake --build Build --target kicad                  # or -DKICAD_TOP="Register 16" for one part
python Tools/eda/kicad.py "Register 16" --check     # any component; --check runs the round trip below
```

`--check` exports the schematic's netlist with kicad-cli, maps it back to the logical pins, and
compares it net for net with the components. It also runs KiCad's ERC. When KiCad is installed,
ctest runs this check as `kicad_round_trip`.

The same project goes on to a placed, routed and checked board, with Gerbers and a BOM. These steps run under
KiCad's own Python, and routing needs Java 21+ and KiCad's Freerouting plugin:

```sh
"C:/Program Files/KiCad/9.0/bin/python.exe" Tools/eda/place.py "Build/KiCad/Register 16"
"C:/Program Files/KiCad/9.0/bin/python.exe" Tools/eda/route.py "Build/KiCad/Register 16"
```

[Tools/eda/README.md](Tools/eda/README.md) explains how each stage works, the files it writes, and the KiCad quirks it
works around.

## Layout

| Path | What it holds |
|---|---|
| `Source/Kestrel/` | The machine definition, shared by every tool |
| `Source/Compiler/`, `Source/Assembler/` | The toolchain |
| `Source/Emulator/` | The reference machine (the definition of correct behaviour) and its CLI |
| `Source/Simulator/` | The gate-level simulator and circuit editor |
| `Tools/` | Python generators for the CPU's hardware |
| `Tools/eda/` | Netlist to KiCad schematic, board placement and routing, and the parts table they use |
| `Build/Components/` | The hardware, as circuit files (generated by the build) |
| `Programs/` | Example and test programs |
